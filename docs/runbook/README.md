

# Implementation Runbook

## Overview
This runbook provides step‑by‑step commands to set up, test, build, and operate the **my Chatbot Life** multi‑tenant SaaS chatbot platform.

## Prerequisites
- Go 1.22+ installed
- Node.js 20+ and npm
- Docker (optional for DB)
- PostgreSQL instance with `pgvector` extension
- `jq` for JSON processing (optional)

## Backend
### Environment variables
```bash
export JWT_SECRET="<your‑secret>"
export DB_DSN="host=localhost user=postgres password=postgres dbname=chatbot sslmode=disable"
export PORT=8080
```
### Run locally
```bash
cd backend
go run ./cmd/api
```
### Tests
```bash
go test ./... -cover
```
### Migrations
```bash

go run ./cmd/migrate up
```

## CI / Reliability Gates
The CI pipeline (GitHub Actions) runs the following stages:
1. Lint (`npm run lint` / `golangci-lint run`)
2. Unit & integration tests (backend & frontend)
3. End‑to‑end Playwright tests (`npm run test:e2e`)
4. Security scans (OWASP dependency‑check, static analysis)
5. Build artifacts
All stages must exit `0` for the PR to merge.

## Operational Procedures
- **Start service**: `docker-compose up -d` (includes DB and backend)
- **Health check**: `curl http://localhost:8080/health`
- **Tenant onboarding**: Use `/api/v1/organizations` endpoint (not in scope).
- **Incident response**:
  1. Collect logs (`docker logs chatbot-backend`).
  2. Run tenant‑leak validation (`go test ./backend/tests -run TestTenantLeak`).
  3. Determine impact: If logs show auth/tenant errors → isolate affected tenant service.
  4. Resume: Restart only the affected container (`docker restart chatbot-backend`).
  5. Relaunch: If migration needed, run (`go run ./cmd/migrate up`) before restart.
  6. Isolation: For persistent failures, scale down tenant‑specific pods and route traffic to a safe fallback.
